# Supabase 账号管理指南（无需后台页面）

> 模型：你（超管）在 Supabase 手动管理「老板/仓库」账号；老板在网页里自己创建
> 「门店/员工」账号。员工登录后只能看到自己老板的商品目录。

---

## 一、一次性准备：拿到 service_role 密钥

老板要能在网页「创建门店账号」，服务端必须配置这把密钥。

1. 打开 supabase.com → 选择你的项目
2. 左下角 ⚙️ **Project Settings → API**
3. 在 **Project API keys** 里找到 **`service_role`** → 点 **Reveal** 复制
4. 粘贴到两个地方：
   - 本地 `.env.local`
   - 线上部署环境（如 Vercel → Settings → Environment Variables）

   ```
   SUPABASE_SERVICE_ROLE_KEY=（粘贴那串密钥）
   ```
   ⚠️ 绝不能加 `NEXT_PUBLIC_` 前缀；绝不能提交进 git。
5. 重启本地 `npm run dev` / 重新部署，才会生效。

---

## 二、一次性：关闭公开注册

即使前端已经删掉了注册入口，也要从 Supabase 彻底关掉，防止有人直接调接口注册。

- **Authentication → Sign In / Providers → Email**（不同版本也可能在 Auth 的 Settings 里）
- 关闭 **"Enable sign-ups" / "Allow new users to sign up"**

---

## 三、创建一个「老板 / 仓库」账号（你来做）

1. **Authentication → Users → Add user → Create new user**
2. 填 **Email + Password**，勾上 **Auto Confirm User**（免邮件确认）→ Create
3. 复制这个新用户的 **User UID**
4. 左侧 **SQL Editor**，运行（把 UID 换成刚才复制的）：
   ```sql
   UPDATE public.profiles SET role = 'warehouse' WHERE id = '粘贴UID';
   ```
   > 默认新建出来是 `store`，这句把它升级成老板（warehouse）。老板不需要 warehouse_id。

---

## 四、老板创建「门店 / 员工」账号（老板自己在网页做）

1. 老板登录 → 顶部 **门店** → **新建门店账号**
2. 填 **邮箱 + 初始密码 +（可选）店名** → **创建账号**
3. 账号即刻可用。把邮箱和密码交给员工，员工登录后只看到这个老板的商品。

> 这一步依赖第一步的 service_role 密钥已配置好，否则会提示「未配置 service_role」。

---

## 五、日常管理（都在 Authentication → Users）

- **改密码**：点该用户 → Reset password（或直接改密码）
- **停用 / 删除账号**：选中用户 → **Delete user**（会连带删掉其 profiles 行）
- **查看某账号归属**（SQL Editor）：
  ```sql
  SELECT id, role, warehouse_id, store_name FROM public.profiles
  WHERE id = '某UID';
  ```
- **把某门店改挂到另一个老板**（SQL Editor）：
  ```sql
  UPDATE public.profiles SET warehouse_id = '另一个老板的UID'
  WHERE id = '门店UID';
  ```

---

## 六、排查

- **老板点「创建账号」报「未配置 service_role」**：第一步没做好——检查 `.env.local` /
  部署环境变量里有没有 `SUPABASE_SERVICE_ROLE_KEY`，改完要重启 / 重新部署。
- **员工登录后看不到任何商品**：确认这个员工 `profiles.warehouse_id` = 对应老板的
  UID，并且商品的 `warehouse_id` 也是同一个老板（见 `multi_tenant.sql` 的回填逻辑）。
- **两个老板的数据混在一起**：说明 `multi_tenant.sql` 还没执行，或回填把旧数据都归给了
  最早那个老板——按需再手动 `UPDATE ... SET warehouse_id` 调整。
